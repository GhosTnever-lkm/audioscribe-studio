# AudioScribe Studio

[![CI](https://github.com/GhosTnever-lkm/audioscribe-studio/actions/workflows/ci.yml/badge.svg?branch=main)](https://github.com/GhosTnever-lkm/audioscribe-studio/actions/workflows/ci.yml) [![Release](https://img.shields.io/github/v/release/GhosTnever-lkm/audioscribe-studio)](https://github.com/GhosTnever-lkm/audioscribe-studio/releases/latest)

**Локальная расшифровка длинных аудиозаписей — до 5 ГБ на файл.** Перетащи запись в приложение, дождись обработки и скачай текст с таймкодами в TXT, SRT, VTT или JSON.

> **Статус:** ранний выпуск; последняя версия и скачиваемый ZIP находятся на странице [релизов](https://github.com/GhosTnever-lkm/audioscribe-studio/releases/latest). Проект рассчитан на локальную обработку; перед использованием на важных записях проверь результат на своём аудио.

AudioScribe Studio — самостоятельный проект GhosTnever. Он не использует облачный API распознавания: аудио декодируется и обрабатывается на компьютере пользователя. Первый запуск выбранной модели требует интернета, чтобы скачать веса модели; само аудио никуда не отправляется. Приложение бесплатно и имеет лицензию MIT.

## Возможности

- Загрузка файла частями по 8 МБ с восстановлением после разрыва соединения; перед продолжением приложение сверяет содержимое уже загруженных блоков.
- Проверка лимита **5 ГБ (5 000 000 000 байт)** перед созданием задания и на стороне сервера.
- Фоновая очередь, пауза и продолжение с последнего завершённого аудиоблока.
- Потоковое декодирование в PCM-блоки ограниченного размера через PyAV. Исходник целиком не читается в оперативную память.
- Локальная модель faster-whisper с выбором размера `tiny`, `base`, `small`, `medium` или `large-v3` и выбором языка/автоопределением.
- Сохранение текста и таймкодов в SQLite после каждого завершённого блока.
- Экспорт TXT, SRT, WebVTT и JSON; аккуратный тёмный интерфейс с перетаскиванием файла.
- Привязка только к `127.0.0.1` по умолчанию; приложение не открывает внешний сетевой сервер.

## Что понадобится

- Windows, macOS или Linux.
- Python 3.11 или новее.
- Свободное место для исходного файла, модели, базы и результатов. Для загрузки файла размером 5 ГБ на диске потребуется примерно 5 ГБ плюс место для модели и служебных данных.
- Для распознавания больших/длинных записей нужно достаточно оперативной памяти. По умолчанию используется CPU-режим int8, чтобы не требовать настроенных CUDA и cuDNN.

Размер файла — это только верхняя граница загрузки, а не обещание скорости. Время зависит от длительности и качества записи, модели и компьютера. На CPU обработка может идти заметно дольше самой записи. Поставить задание на паузу можно между блоками; уже сохранённый текст останется.

## Установка и запуск

В PowerShell из папки проекта:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e ".[transcription]"
audioscribe
```

Открой `http://127.0.0.1:8765`. При первом задании faster-whisper загрузит выбранные веса модели из Hugging Face Hub и сохранит их в стандартном локальном кэше. Если `py` не установлен, создай окружение обычной командой `python -m venv .venv`.

На Linux/macOS активируй окружение `source .venv/bin/activate`, установи `python -m pip install -e '.[transcription]'`, затем запусти `audioscribe`.

Чтобы хранить данные в другом месте, задай `AUDIOSCRIBE_HOME` до запуска. Размер сегмента по умолчанию — 5 минут. Его можно изменить переменной `AUDIOSCRIBE_SEGMENT_SECONDS`; меньшие блоки дают более частые точки сохранения, большие — могут лучше сохранять контекст речи, но требуют больше памяти и времени.

## Данные и конфиденциальность

Исходные файлы, SQLite-база и расшифровки сохраняются в `%USERPROFILE%\.audioscribe` на Windows или `~/.audioscribe` на macOS/Linux. Удаление задания удаляет его аудиофайл и текст из базы. База и исходные файлы не шифруются самим приложением — используй шифрование диска, если оно тебе нужно. Скачивание весов модели при первом запуске идёт из Hugging Face Hub; сетевой запрос не содержит аудиофайл.

Приложение не отправляет телеметрию. Оно слушает только localhost; не перенаправляй порт наружу и не меняй `AUDIOSCRIBE_HOST` на публичный адрес.

## Текущие ограничения

- Пока один фоновый worker обрабатывает одну запись за раз; очередь хранит остальные.
- Остановка/пауза срабатывает между блоками распознавания. Уже начавшийся вызов модели нельзя прервать мгновенно.
- Используется CPU int8 по умолчанию. Настройка GPU и управление расходом VRAM появятся отдельно.
- Блоки перекрываются на 2 секунды; фраза, пересекающая границу блоков, сохраняется из последующего блока, где доступно аудио с обеих сторон. При продолжении задание повторно декодирует уже обработанные блоки с начала файла, но пропускает повторное распознавание. Для контейнеров без длительности в метаданных приложение сейчас выдаёт понятную ошибку.
- Это текстовая расшифровка с таймкодами уровня сегментов. Разделение по говорящим, редактирование таймкодов, словные метки и видеофайлы как отдельный режим пока не включены.
- На время загрузки требуется место под исходный файл; приложение не стримит его напрямую в модель.
- Очень длинная запись не всегда будет обработана быстро: 5 ГБ может соответствовать десяткам часов аудио.

## Разработка

```powershell
python -m pip install -e ".[dev]"
python -m unittest discover -s tests -v
```

В GitHub Actions тесты запускаются на Windows и Ubuntu. См. [CONTRIBUTING.md](CONTRIBUTING.md) и [архитектурную заметку](docs/architecture.md).

## План развития

1. Стабилизировать приём больших файлов, восстановление задания и экспорт на Windows/Linux.
2. Измерить скорость/память на типичных размерах моделей и добавить автоматическую оценку времени.
3. Добавить опциональное разделение по говорящим и редактирование транскрипта.
4. Добавить пакетную очередь, словари терминов и пресеты экспорта.
5. Подготовить подписанные portable-сборки после повторяемой CI-сборки и интеграционных проверок.
